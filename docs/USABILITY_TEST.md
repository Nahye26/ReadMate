# 가설 2와 사용성 테스트 시나리오 (초안)

작성일: 2026-11-17 · 상태: 초안. `(미정)`은 팀이 정해야 하는 값이고, 아래 제안은 근거가 있는 것만 적었다.

## 1. 가설 2 칸 (재작성안)

**기존**: 1~2문장 발췌보다 긴 문장을 읽을 때 과제 수행·이해도가 높을 것이다. (Promptfoo 프롬프트 비교 실험으로 검증)

**수정**: 이 서비스는 "검증"이 아니라 **선행연구 근거의 설계 채택과 사용성 확인**으로 다룬다.

- 설계 채택: 읽기 분량은 조건 B(핵심 청크 + 같은 절의 앞 1개 + 뒤 1개, 최대 3청크)를 기본으로 한다. 근거는 배민령·이병민(2018)의 "짧은 지문 + 원문 문단 1~2개"다. 이 연구는 영어 읽기를 다뤘고 글자·단어 수 기준을 주지 않으므로, 한국어 최소 분량의 근거로 쓰지 않는다.
- 확인할 것: 웹앱 사용성 테스트에서 B의 읽기 부담이 수용 가능하고 미션을 끝까지 하는지 본다.
- 축소 기준(기각 기준): B에서 읽기 부담이 높거나 미션 완료율이 낮으면 범위를 "앞 1개만"으로 줄인다. (`CONFIG.ctxAfter = 0`)
- 하지 않는 주장: A와 B 중 어느 쪽이 이해도·과제 수행을 높이는지는 이 테스트로 말하지 않는다.

**정해야 할 것**: "높다/낮다"의 기준값. 기준을 절대값으로 두려면 팀이 값을 정해야 하고(미정), 아래 3절의 작은 A/B를 넣으면 기존 파일럿 규칙("B의 읽기 부담이 A보다 1점 이상 높거나 완료율이 떨어지면 축소")을 그대로 쓸 수 있다.

## 2. 테스트 구성

| 항목 | 내용 |
|---|---|
| 방식 | 배포한 웹앱으로 진행한다. 질문 세트는 논문마다 AI가 A 기준으로 1회 생성·고정하고, 연구자가 검토한 뒤 쓴다. |
| 참가자 | (미정) 대학생. 아래 3절의 절충안을 쓰면 4~6명. |
| 논문 | (미정) 1~2편. 참가자가 공유 자료를 쓰도록 연구자가 `sources.shared`를 켠다. |
| 과제문 | (미정) 논문마다 고정한다. 과제문이 바뀌면 질문 세트도 새로 만들어진다. |
| 모드 | 실험 모드(안내 수준·질문 깊이 고정). 조건은 앱이 배정한다. |
| 동의 | 요약 저장 / 답변 원문 저장 두 가지를 분리해서 받는다. 외부 LLM(Gemini)으로 자료와 답변이 전송된다는 점과 학습 조항 포함 여부를 동의서에 적고 IRB 담당자에게 확인한다(기존 결정). |

## 3. 작은 A/B를 테스트 안에 넣는 절충안

- 4~6명이 논문 2편을 하나씩 읽되, 한 편은 A, 다른 편은 B로 읽는다. 조건 순서는 참가자마다 교차한다.
- 4~6명으로는 순서와 논문 효과를 완전히 맞출 수 없고 통계 검정도 못 한다. **방향을 보는 기술 통계**로만 쓰고, 보고서에도 그렇게 적는다.
- 논문을 1편만 쓰면 한 사람이 A와 B를 둘 다 하면 학습 효과가 생기므로, 그때는 사람 간 비교가 된다(참가자 수가 더 필요).

## 4. 진행 순서 (참가자 1명)

1. 연구 안내와 동의(2종). 거부해도 사용할 수 있게 한다.
2. 앱 접속(익명 로그인), 한 줄 사용 안내.
3. 논문 1: 과제문 확인 → 미션 3개(읽기, 질문, 힌트·피드백) → 인출과 회상 예측 → 읽기 부담 1~5.
4. 논문 2: 반대 조건으로 같은 순서를 반복. (3절의 절충안을 쓸 때)
5. 사후 질문: 막힌 곳, 헷갈린 화면, 분량 인상. 사용성 척도 사용 여부는 (미정).

## 5. 측정 항목 (앱이 이미 기록하는 것)

| 보려는 것 | 기록 위치 |
|---|---|
| 완료율 | `summary.missions_done`, `missions_unresolved` |
| 읽기 부담 | `summary.reading_load` (1~5) |
| 중도 이탈 | `summary.exit_reason` |
| 도움 사용 | `summary.hint_level`, `answered_with_hint` |
| 제공 분량 확인 | `summary.text_units_provided` (A는 1, B는 1~3) |
| 인출·보정 | `recall_actual`, `recall_prediction`, `calibration` |
| 오류·막힘 | `events` (예: 피드백 호출 실패) |

사용성 문항(과업 성공 여부, 소요 시간 등)과 관찰 기록 양식은 (미정)이다. 소요 시간은 `events`의 경과 초로 얻을 수 있다.

## 6. 정해야 할 순서

1. 참가자 수와 절충안(3절) 채택 여부 → 기준값 결정 방식(1절)이 따라온다.
2. 논문 1~2편과 과제문 → 질문 세트 생성·검토.
3. IRB와 동의서 문구.
4. (별개) 임베딩 모델: 현재 `gte-small`은 영어 중심이라 한국어 논문이면 검색 품질을 먼저 확인해야 한다.
